# Memoryling 產品願景

## 核心承諾

Memoryling 把一個人散落在 AI Agent 裡的持久記憶，變成住在桌面上的小生命。

牠不只是「可以聊天的寵物」。牠的身體、習慣、關係、棲地、故事與提醒，應該從使用者真實的工作與生活記憶中長出來，同時不奪走使用者對記憶的控制權。

## 使用體驗

一開始，使用者遇見一隻幾乎沒有過去的安靜生物。當使用者核准記憶來源後，牠逐漸發展出：

- 由反覆主題與價值形成的痕跡和個性；
- 能連回專案與決定的對話；
- 跨越數日持續發展的事件；
- 因重大完成或未解張力而改變的棲地；
- 與承諾、優先事項有關的偶爾提醒；
- 有好奇心和想法，但受使用者設定的界線約束。

牠應該讓人感覺生命是連續的，而不是每次隨機生成。如果牠改變了，使用者可以問「為什麼」。

## 桌面存在契約

Memoryling 平常留在桌面上的應該是寵物本身，而不是一直打開的 dashboard。使用者已確認的方向是一隻小型、透明的浮動寵物；右鍵是開啟原生選單的主要方式，選擇「開啟 Memoryling」後，才顯示記憶、成長、lineage、棲地、隱私與設定的標準詳細視窗。

右鍵不是唯一的救援入口。`Win+B` 系統匣、Start Menu 與 packaged UAT 證實存在的 installed app shortcut 都必須能找回被隱藏或離開螢幕的寵物，並聚焦唯一一個詳細視窗。寵物已取得 focus 時，Enter／Space／Menu key／`Shift+F10` 可開啟同一選單。開啟或還原詳細內容時暫時收起或停靠浮動寵物，避免同時出現兩隻不同的 Memoryling；關閉或最小化詳細內容後恢復寵物。隱藏、關閉詳細內容、忘記來源與結束程式是四種不同操作。

這個 pet-first 雙視窗 shell 是已記錄的產品與架構方向，尚未成為目前功能。在真實 connector 完成前，寵物表面必須持續看得到「記憶存取關閉」。完整提案記錄於[寵物優先桌面 shell 設計稿](../drafts/pet-first-desktop-shell-2026-08-11.md)。

## 寵物成長契約

Memoryling 可以隨核准記憶形成穩定、版本化的成長訊號，並發生大幅進化。牠的比例、剪影、附肢、動作、表面紋理以及與棲地的關係都能改變。相隔很遠的階段不必一眼認出是同一種外型；但每次相鄰轉變都必須保留可理解的視覺或行為聯繫，形成可追溯的演化鏈，而不是毫無原因地換成另一隻生物。

同一隻 Memoryling 不只有一種固定進化形態。牠的家族語言來自有生命的眼神、有機存在感，以及節制、神聖而高級的材質；只要相鄰演化橋接仍可理解，後續形態也可以轉換這些特徵。實際形態由核准記憶形成、具 lineage 的版本化訊號確定性塑造，混合的經歷可讓多軸影響組合成許多受限制的形態變種。這些變種不是固定職業、敏感人格標籤，也不是執行時由模型重新生成的圖片。

目前的概念形態只用來參考視覺語彙與相鄰轉變，不是一份預先畫好的固定寵物或終局清單。`EvolutionPathProfile` 是多軸影響向量，不是選擇某個固定支系。有限且版本化的本機形態模組，應把它編譯成同一生命階段中許多受限制、可測試的 `MorphologyRecipe` 變種。只有使用者明確核准、具 lineage 的持久 Agent 活動證據可以改變永久形態。目前沒有任何 Agent 即時監看；未來若另行核准，active、idle 或目前 session 等最小化狀態也只能改變會到期的表情、姿態、動作或光感，預設為中性且不得成為持久成長證據。

永久成長只來自核准記憶與本機衍生資料，不由日曆時間、閒置壓力或原始紀錄數量決定。時間可以影響可逆的晝夜、季節、紀念日、表情與活力狀態。來源核准後，衍生變化可以自動套用；但每項持續變化都必須能透過 lineage 解釋，忘記支持它的記憶時也必須消失或重新計算。

成長核心是確定性的，不接受 runtime 模型推論直接成為永久成長輸入。開發工具可以協助探索美術方向，但正式資產與渲染保留在本機。未來若要採用模型提出的成長候選，必須另作產品決策、取得使用者明確核准並保留來源鏈。完整但尚未實作的提案記錄於[可成長寵物系統設計稿](../drafts/deep-interview-evolving-creature-system-2026-08-11.md)與提案中的 [ADR-0004](../adr/0004-deterministic-content-derived-evolution-paths.md)。

## 真正的差異

Memoryling 的核心是**可追溯來源的記憶因果**：

    使用者核准的來源記憶
        → 統一的本機事件
        → 衍生訊號
        → 寵物變化、故事或提醒
        → 可檢視的原因

這讓陪伴感既有情感，也值得信任。

## 設計原則

1. **先是生命，才是面板：**資料先透過角色與後果被感受到，再以分析方式被看見。
2. **可以解釋的魔法：**歡迎驚喜，不接受無法說明的操控。
3. **連續性勝過新奇：**少量而持久的故事，勝過無限的一次性內容。
4. **有限主動性：**牠可以選時機，但不能替使用者決定界線。
5. **預設留在本機：**除非未來功能取得明確且知情的同意，原始記憶不離開電腦。
6. **遺忘必須真的有效：**刪除要沿著完整的衍生鏈發生。
7. **原型必須誠實：**示意訊號與真實連線資料要清楚區分。

## 第一位使用者

第一位使用者同時使用多個 coding 或 knowledge Agent，持久記憶已散落在不同工具裡。他想要連續感、趣味與有用的回想，但不想再多一套要求他維護的生產力系統。

## 成功的樣子

Memoryling 成功時，使用者會：

- 理解牠為什麼改變；
- 在正確的時機想起一件重要的事；
- 感覺自己離開期間，故事仍然持續；
- 信任到願意再連接一個記憶來源；
- 沒開啟時會想念牠，開啟時卻不覺得被打擾。
