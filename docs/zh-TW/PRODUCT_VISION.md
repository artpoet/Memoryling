# Memoryling 產品願景

## 核心承諾

Memoryling 把一個人散落在 AI Agent 裡的持久記憶，變成住在桌面上的小生命。

牠不只是「可以聊天的寵物」。牠的身體、習慣、關係、棲地、故事與提醒，應該從使用者真實的工作與生活記憶中長出來，同時不奪走使用者對記憶的控制權。

## 使用體驗

一開始，使用者遇見一隻幾乎沒有過去的安靜生物。當使用者核准記憶來源後，牠逐漸發展出：

- 由反覆主題與價值形成的痕跡和個性；
- 能連回專案與決定的對話；
- 跨越數日持續發展的事件；
- 因重大完成或未解張力而改變的棲地；
- 與承諾、優先事項有關的偶爾提醒；
- 有好奇心和想法，但受使用者設定的界線約束。

牠應該讓人感覺生命是連續的，而不是每次隨機生成。如果牠改變了，使用者可以問「為什麼」。

## 桌面存在契約

Memoryling 平常留在桌面上的是寵物本身，而不是一直打開的 dashboard。v0.2.0 foundation 已實作一隻小型、透明的浮動寵物；右鍵會開啟原生選單，選擇「開啟 Memoryling」後，才顯示記憶、成長、lineage、棲地、隱私與設定的標準詳細視窗。

右鍵不是唯一的救援入口。系統匣、Start Menu 與 installed shortcut 都能找回單一常駐程序並聚焦唯一的詳細視窗；目前主機已驗證冷啟動與常駐時再次啟動。寵物取得 focus 時，Enter／Space／Menu key／`Shift+F10` 可開啟同一選單。開啟詳細內容時會收起寵物，避免同時出現兩隻不同的 Memoryling；關閉或最小化詳細內容後恢復寵物。隱藏、關閉詳細內容、忘記來源與明確 Quit 是不同操作。`Win+B`、延伸 DPI／螢幕救援、輔助科技與 sign-out／shutdown 仍待專門實機驗收。

這個 pet-first 雙視窗 foundation 已以 Rust-owned lifecycle 與窄化 render-state boundary 實作；完整驗收仍由[寵物優先桌面 shell 設計稿](../drafts/pet-first-desktop-shell-2026-08-11.md)與 proposed ADR-0003 追蹤。在真實 connector 完成前，寵物表面仍持續顯示「記憶存取關閉」。

## 寵物成長契約

Memoryling 可以隨核准記憶形成穩定、版本化的成長訊號，並發生大幅進化。牠的比例、剪影、附肢、動作、表面紋理以及與棲地的關係都能改變。相隔很遠的階段不必一眼認出是同一種外型；但每次相鄰轉變都必須保留可理解的視覺或行為聯繫，形成可追溯的演化鏈，而不是毫無原因地換成另一隻生物。

同一隻 Memoryling 不只有一種固定進化形態。牠的家族語言來自有生命的眼神、有機存在感，以及節制、神聖而高級的材質；只要相鄰演化橋接仍可理解，後續形態也可以轉換這些特徵。實際形態由核准記憶形成、具 lineage 的版本化訊號確定性塑造，混合的經歷可讓多軸影響組合成許多受限制的形態變種。這些變種不是固定職業、敏感人格標籤，也不是執行時由模型重新生成的圖片。

目前的概念形態只用來參考視覺語彙與相鄰轉變，不是一份預先畫好的固定寵物或終局清單。`EvolutionPathProfile` 是多軸影響向量，不是選擇某個固定支系。有限且版本化的本機形態模組，應把它編譯成同一生命階段中許多受限制、可測試的 `MorphologyRecipe` 變種。只有位於授權範圍內、具 lineage 的持久 Agent 活動證據可以改變永久形態。目前沒有任何 Agent 即時監看；未來若另行核准，active、idle 或目前 session 等最小化狀態也只能改變會到期的表情、姿態、動作或光感，預設為中性且不得成為持久成長證據。

未來的證據優先順序是：**A：Agent 常用活動 > C：累積歷程與有意義的成果 > B：合作方式**。A 控制主剪影與主要動態；C 控制 maturity、里程碑結構與具 lineage 的永久印記；B 只能調整一項受限制的局部節奏或互動 accent。coding、research 或 writing 等內容領域只能影響 allowlist 內的材質或表面紋理 accent，不能決定物種、身體類別或固定外型。

未來 real-source 流程必須取得一個明確同意 scope，範圍包含一個選定來源、其 adapter version、選定資料類別與允許的成長用途。系統可在該範圍內自動於本機進行確定性衍生；另一個來源必須建立另一個 scope，新增資料類別或用途則必須建立新 consent revision。近期證據一律先表現為具 TTL 的表情、姿態、動作或光感反應。永久重塑必須由多組已去重、彼此獨立且具有有意義成果語意的證據，在版本化門檻下持續一致後才可發生。日曆時間、開啟時數、來源量與原始紀錄數量都不算 XP。每項永久變化都必須能透過 lineage 解釋，忘記支持它的記憶時也必須消失或重新計算。

成長核心是確定性的，不接受 runtime 模型推論直接成為永久成長輸入。開發工具可以協助探索美術方向，但正式資產與渲染保留在本機。未來若要採用模型提出的成長候選，必須另作產品決策、取得使用者明確核准並保留來源鏈。這整套成長契約目前都只是設計：現行產品仍只有 fixture，尚未實作 real-source 同意流程或證據驅動形態。詳細提案記錄於[可成長寵物系統設計稿](../drafts/deep-interview-evolving-creature-system-2026-08-11.md)、[Agent 記憶變體規則](../drafts/deep-interview-agent-memory-variation-rules-2026-08-12.md)與提案中的 [ADR-0004](../adr/0004-deterministic-content-derived-evolution-paths.md)。

## 真正的差異

Memoryling 的核心是**可追溯來源的記憶因果**：

    使用者核准的來源記憶
        → 統一的本機事件
        → 衍生訊號
        → 寵物變化、故事或提醒
        → 可檢視的原因

這讓陪伴感既有情感，也值得信任。

## 設計原則

1. **先是生命，才是面板：**資料先透過角色與後果被感受到，再以分析方式被看見。
2. **可以解釋的魔法：**歡迎驚喜，不接受無法說明的操控。
3. **連續性勝過新奇：**少量而持久的故事，勝過無限的一次性內容。
4. **有限主動性：**牠可以選時機，但不能替使用者決定界線。
5. **預設留在本機：**除非未來功能取得明確且知情的同意，原始記憶不離開電腦。
6. **遺忘必須真的有效：**刪除要沿著完整的衍生鏈發生。
7. **原型必須誠實：**示意訊號與真實連線資料要清楚區分。

## 第一位使用者

第一位使用者同時使用多個 coding 或 knowledge Agent，持久記憶已散落在不同工具裡。他想要連續感、趣味與有用的回想，但不想再多一套要求他維護的生產力系統。

## 成功的樣子

Memoryling 成功時，使用者會：

- 理解牠為什麼改變；
- 在正確的時機想起一件重要的事；
- 感覺自己離開期間，故事仍然持續；
- 信任到願意再連接一個記憶來源；
- 沒開啟時會想念牠，開啟時卻不覺得被打擾。
